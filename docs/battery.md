# STC3117 电量策略（0.4.2）

修正目标是旧 DIY 只启动库仑计、未设置初始电量，以及满充末段显示偏低。软件测试不能证明某台设备的电池已校准：原有的低电压、欠压锁存或电池故障必须分别诊断。

## 来源与移植范围

- 用户提供的 [LiJinLiJin/stc3117-fuel-gauge](https://gitcode.com/LiJinLiJin/stc3117-fuel-gauge)，固定提交 `9b9fadf6bd2f3713620a2c5abdbb8b54608cefd4`。已核对 README、驱动与四份补丁。该树是 GPL-2.0 Linux DKMS 驱动，不能作为 ESP-IDF 驱动直接编译；本项目没有复制其 Linux 驱动代码，依据寄存器规范独立实现初始化和满充策略。
- [STC3117 数据手册](https://www.st.com/resource/en/datasheet/stc3117.pdf)，DocID025792 Rev 4：16 位读数一次事务读取；电流 14 位有符号，电压有符号；OCV/SOC 表在 `0x30` / `0x50`，长度 32 / 16 字节；OCV 或 SOC 写入初始化两种估算器。
- [TypixNode MIT 固件修复](https://github.com/TypixNode/TypixDeck-esp32s3-firmware/commit/7c1b0d70ae7e2db3b7d0a389cffb4a04605e372d)：沿用原装 604070 的 4.2 V OCV 曲线、SOC 断点及共享 RAM 布局，保留项目 MIT 声明。

朋友树中的默认 OCV 曲线最高点是 4.32 V，不能直接当作原装 4.2 V 电芯曲线使用。其 README 的 CM5 / RP1 总线编号也没有搬到 CM4：ESP 使用现有板级 I2C 句柄与 MUX 归属，不按计算模块型号选择总线。

## 初始化和接管

1. 在已有 ESP 总线所有权内读取 ID、状态和整组测量，检查器件、电压、SOC 和故障位。CW2015 正常且电压有效时，用它交叉检查；两路电压相差超过 200 mV 暂不采用 STC 值。CW 的百分比不会用于校准 STC。
2. POR / 未配置启动时，用 POR OCV 或 `V − I×Ri` 作为初始 OCV。原装参考参数为 2400 mAh、10 mΩ 采样电阻、140 mΩ 整包参考内阻。140 mΩ 来自上游样机，**不是本机 CM4 实测**；换过电池需核对配置，不按 CM 型号硬编码。
3. 对已经运行的计量器，只有未播种且 SOC <1% / 估算 OCV >3.7 V，或已知旧 DIY `CC=605, VM=614`、SOC <10% 的错误起点，才修复。先用间隔 ≥4 s 的两次采样确认转换计数前进，冻结读数不触发此修复。
4. 健康运行值直接接管，保留现有容量/内阻系数，包括 Linux 学习值。不能因没有新 RAM 标记就重置任意正常 Linux 驱动的结果。已播种而仅暂停的计量器恢复运行时也保留 SOC 和系数。
5. 初始化先写 CRC 有效的 pending 记录，再停止计量、写全两张表并读回、配置系数、恢复运行、写 OCV。每步失败立即停止；最后才写并读回成功标记。中途中断可按 pending 记录重试，明显变化的电压不用旧 OCV。

共享 RAM 仍为 testword `0x53A9`、byte 10 成功标记 `0x5D`、CRC-8/poly `0x07`。pending 使用 byte 10=`0xA6`、byte 11–12 暂存初始 OCV，成功后清理。RAM 中的 SOC 与配置一起更新，不把 0 当作有效保存值。

BATFAIL / UVLOD 表示需要另行检查的电池事件，显示未知并保留故障；本版不会自动清掉这两种故障或发送软复位。真正低电量仍可显示 0%，不会把 2.7 V 的低电压强行修正成高电量。

## 满充判定

采用朋友提出的 ±100 mA 净电流窗口，适配电池直通供电、涓流期间电流正负摆动。增加以下约束：

- INA219 确认 USB 输入 >4 V；读失败不当作已插电。
- 当前连续观察期曾看到 ≥200 mA 充电，且距最后一次这样的采样不超过 30 分钟。
- STC 的 SOC ≥80%，电压 4.15–4.25 V，温度 0–45 ℃。
- 净电流在 ±100 mA 内持续 **30 个实际秒**，每次采样都新鲜且转换计数前进。
- MUX 切换、I2C 失败、采样间隔 >7.5 s、欠压或不满足阈值都会打断相应观察。拔电取消充电记录。

满足后写 `SOC=51200` 并读回；成功才向 UI 报告 100%。同一满充过程不重复写入。该判定只调整估算器，**不控制充电器，也不是电池安全保护**。

未移植自动容量系数学习。它需要完整充电会话；MUX 切走时 ESP 无法读取真实电池电流，遗漏期间不能按固定电流积分。现有 `batt_log` 的 NVS 续航容量估算与 STC 配置隔离，不能把一个估算值当作电芯实测容量。后续如实现学习，应使用实际时间间隔、净电荷、完整会话、每次限幅，并独立验收。

## 采样、失败和显示

`batt_log` 每 5 s 调用一次唯一的计量器维护入口；UI 只读经过验证的快照。切回 ESP 后一般需 5–10 s 获得两个采样，刚初始化还可能多一个周期；期间显示 `--`。7.5 s 以上的缓存不再显示。历史页原有的 CW 参考回退仍明确标注，不参与 STC 修正。

完整的计量器事务与已有 MUX 切换 / I2C 恢复路径共用静态互斥量。没有新增 MUX 切换、改变引脚、主机开关机或充电器动作。`BATTERY_STATUS` 仍是有界、只读的 `TD_BATT v=2`，诊断不会触发播种或复位；串口现有日志另记录固定状态码（0 等待、1 正常、2 I2C、3 电池故障、4 冻结、5 无效、6 已初始化、7 满充校正）。

## 验证

`tests/test_sensors.py` 编译生产 C 代码并使用 ASan/UBSan；覆盖诊断零写入、RAM CRC、冷启动、旧配置错误起点、Linux 接管、保留学习系数、每个写入步骤失败后的恢复、表读回失败、真实低电量、故障/电压冲突、计数回绕/冻结、缓存过期、MUX 禁止访问及 EOC 的成功/失败/中断。

整套本地行为检查与 ESP-IDF 5.5.1 构建通过。**本版没有真机刷写、充放电周期或跨 Pi/ESP 实测，`hardware_verified=false`。** 真机验收需确认实际电池规格，采集白名单 `BATTERY_STATUS` 两次并对比电压/计数，验证切屏不重复播种，再观察一次接近满充过程。若出现 BATFAIL/UVLOD 或两路电压冲突，先诊断硬件状态，不以显示 100% 作为成功标准。
